## 1. brand.json 항목

```json
{
  "brand_name": "뷰티소",                       // 카드·자막·캡션·마무리 대사에 들어가는 한글 브랜드명
  "brand_name_en": "BEAUTYSO",                  // 영문(릴스 라벨 "BEAUTYSO LAB", 진행자 문단 "every Beautyso video")
  "brand_slug": "beautyso",                     // 파일명용 영문 소문자(beautyso_logo.png)
  "brand_alt": "",                              // 한자·부가 표기(선택). 비우면 가전소의 '家電所' 자리는 지워진다
  "tagline": "화장품, 제대로 알고 사는 곳",       // CTA 장 원형 로고 옆 한 줄
  "domain": "화장품",                            // 업종. "가전"이 아니면 업종 문장 점검 목록을 만든다
  "consult_url": "http://pf.kakao.com/_xxxx/chat", // 상담 QR 이 여는 주소(카드 배지·CTA·릴스 엔딩·FB 캡션)
  "consult_channel": "카카오톡",                 // 상담 채널 이름(문구 속 '카카오톡' 자리)
  "github_repo": "owner/beautyso-cardnews",     // 새 저장소(공개). 발행 이미지 주소에 쓰인다
  "drive_folder_id": "",                        // (선택) 구글 드라이브 '릴스영상' 폴더 ID. 없으면 비움
  "logo_file": "logo.png",                      // brand.json 기준 상대 경로 가능
  "logo_medal_crop": null,                      // (선택) CTA 원형 로고에 쓸 영역 [왼,위,오,아래] 비율. 비우면 자동
  "host_image": "",                             // (선택) 릴스 진행자 기준 이미지
  "palette": {"navy": "#1A2A4A", "blue": "#2E5EAA", "ice": "#DCE8F5", "orange": "#FF8A3D"}
}
```

`assets/brand.example.json` 을 복사해 채운다. 모르는 값(드라이브 폴더, 진행자 이미지)은 비워 두고 나중에 넣어도 된다.

## 2. 로고·색·진행자 준비물

**로고**
- 한 가지 색(진한 선) 로고가 가장 잘 나온다. 표지에서는 `palette.navy` 한 색으로 다시 칠해지고, 어두운 표지에서는 `ice` 색 둥근 배지 위에 올라간다. 컬러 로고는 단색으로 바뀐다는 점을 사용자에게 알린다.
- 투명 PNG 도 된다(스크립트가 흰 배경 정사각형으로 정리한다). 가로로 긴 워드마크는 표지 로고 칸(가로 약 150px)에 맞춰 작아지므로, 심볼(정사각형에 가까운 마크)이 있으면 그것을 권한다.
- CTA 마지막 장의 원형 로고는 `logo_medal_crop` 영역을 쓴다. 자동값은 로고 전체를 감싸는 정사각형이다. 심볼만 원 안에 넣고 싶으면 check 결과의 card7 을 보고 비율을 조정해 다시 만든다(가전소는 `[0.222, 0.1667, 0.778, 0.7222]` — 로고 위쪽 얼굴 부분).

**색(palette)** — 이름은 코드 속 이름이고, 역할로 고른다.
| 이름 | 역할 | 고르는 법 |
|---|---|---|
| navy | 가장 진한 기본색: 표지 배경(navy 표지), 제목·테두리·로고 | 흰 글씨가 잘 읽히는 아주 진한 색 |
| blue | 핵심 수치·표 값·번호 | navy 보다 밝고 채도 있는 색 |
| ice | 옅은 배경(ice 표지·표 카드)·배지 | 거의 흰색에 가까운 옅은 색 |
| orange | 강조 한 가지: 태그·FILE 번호·VS·특가·주의 | navy 와 대비되는 따뜻한 색 |

보조색(페이지 번호·줄무늬 등)은 스크립트가 같은 관계로 다시 계산한다. 결과 카드를 열어 글씨가 잘 읽히는지 반드시 눈으로 본다. 표지색 이름(`cover_color: navy|ice|white|orange`)은 그대로 쓰므로 문서 속 "네이비" 등의 색 이름은 바꾸지 않아도 동작한다(원하면 ROUTINE_PROMPT [디자인 규칙 요약]의 색 이름만 고친다).

**릴스 진행자**
- ROUTINE_PROMPT.md step3 7번의 `HOST:` 문단과 `assets/reel_host/host.jpg` 가 짝이다. 브랜드에 맞는 인물로 바꾸려면 둘을 함께 바꾼다(docs/reel_host.md 의 프롬프트도 같은 묘사로).
- 마무리 대사 "추가 정보와 문의는 <브랜드>에서!" 와 FINAL SHOT(오른쪽 위 QR 자리)은 그대로 둔다. reel_overlay.py 의 QR 패널 위치(END_BOX)와 맞물려 있다.

## 3. 업종에 맞게 다시 쓰는 부분

스크립트는 브랜드명·주소·색만 바꾼다. 아래는 사람이 읽는 판단 규칙이라 업종에 맞게 Claude 가 직접 다시 쓴다. `REBRAND_TODO.md` 에 해당 줄 번호가 있다.
**원칙: 파이프라인 규칙(파일 이름·장수·카드 유형·푸시 순서·approval.txt 마지막·게시 금지)은 건드리지 않는다. 바꾸는 것은 "무엇을 어디서 찾고 어떻게 말하는가"뿐이다.**

| ROUTINE_PROMPT.md 위치 | 처리 |
|---|---|
| `<role>` | 다시 쓰기: 브랜드 소개(무슨 계정인지), 톤(누가 설명하는 말투인지) |
| step0 | 그대로 |
| step1 -1·0·b~g | 그대로 |
| step1 0 a) 우선 이슈 ①~⑤ | 다시 쓰기: 업종의 리콜·안전, 제도·지원금, 대형 행사, 주요 브랜드 신제품 등. 가전소의 애플·노트북 항목은 지운다 |
| step1 1 검색 출처·검색어 | 다시 쓰기: 업종 뉴스 섹션, 공식 기관·협회, 검색어 예 |
| step1 2 저장·공유 동기 예 | 업종 예로 바꾸기(원칙 문장은 유지) |
| step1 4 유형 A~D 의 예 | 괄호 속 예시만 업종 예로(유형 체계·표지색 규칙은 유지) |
| step2 1 확인 순서 | 다시 쓰기: 브랜드 공식 → 업종의 신뢰 판매처·기관 → 뉴스. '롯데하이마트 온라인몰' 은 지운다 |
| step2 3 전문성 | "가전 전문가" → 업종 전문가, 1차 출처 예(한전 등)를 업종 기관으로 |
| step2_5 제품 이미지 | 출처 예를 업종으로. `illust:` 종류 목록은 4번 참고 |
| step3 [생성 방법]·[표지 콘텐츠 규칙]·[표지 디자인 규칙]·[대표 로고]·[포스터형]·[구조]·[검수] | 그대로(예시 문장 속 가전 수치만 업종 예로 바꿔도 됨) |
| step3 7 HOST·컨셉 12종 | HOST 는 2번 참고. 컨셉 12종은 이름은 유지하고 설명 속 예(드럼 안·김장 등)를 업종 소품으로 |
| step3 [제품 뉴스형]·[본문 전문성]·[말투] | 단위(kW·L 등)와 예시를 업종으로 |
| step3 [상담 배지] | "롯데하이마트 정왕역점…" 줄을 지운다(가전소 전용 금지어). 새 브랜드에 금지어가 있으면 그것으로 |
| step3_5·step4·step5 | 그대로(해시태그 #브랜드는 이미 바뀜) |
| `<constraints>` 마지막 줄 | 가전소 매장 금지 문구를 지우거나 새 브랜드 것으로 |

CLAUDE.md 는 ROUTINE_PROMPT.md 의 요약이다. 같은 부분(일러스트 종류 목록, 주제 선정의 네이버·애플 문장)을 똑같이 맞춘다.
다 고친 뒤 `grep -nE "가전|하이마트|한전|애플|김장" ROUTINE_PROMPT.md CLAUDE.md` 로 남은 곳이 의도한 것인지 확인한다.

## 4. 제품 도면(일러스트) — 가전이 아닌 업종

표지에는 항상 제품 이미지(실물 컷아웃 또는 `illust:종류` 도면)가 들어간다. 도면은 `assets/blueprints/<종류>_<dark|light|orange>.png` 이고 없는 종류는 `generic` 으로 대체된다.
- **가전 업종**: 그대로 쓴다. 색을 바꿨다면 도면을 다시 그린다:
  `CHROME=/opt/pw-browsers/chromium bash design/blueprints/render_png.sh` (macOS 는 CHROME 생략)
- **다른 업종**: 가전 도면은 맞지 않는다. 둘 중 하나를 고른다.
  1. 실물 사진 위주로 운영: step2_5 를 "실물 컷아웃 우선, 못 구하면 `illust:generic`" 으로 두고, 가전 종류 목록을 지운다. 빠르게 시작할 때 권장.
  2. 업종 도면을 새로 그린다: `design/blueprints/build.py` 의 규칙(세로형 440×960·가로형 900×360, 선 굵기·강조 한 곳)대로 `D` 에 새 종류를 넣고 `ORDER` 에 추가 → render_png.sh 로 PNG 생성 → 가로형이면 gen_cards.py 의 `LAB_LANDSCAPE` 에 추가 → ROUTINE_PROMPT step2_5 의 종류 목록 갱신.
- 어느 쪽이든 `generic` 도면은 남겨 둔다(없는 종류의 대체).

## 5. 첫 콘텐츠 계획

`plan/content_plan.md` 는 빈 틀로 만들어진다. 사용자와 업종·타깃을 짧게 확인한 뒤 4~6주치를 채운다.
- 주차별 테마(계절·행사·기한) → 날짜별 행: 날짜·구분(계획/이슈)·주제·저장·공유할 이유·유형·표지 제안·결과(빈칸).
- 화·금은 '이슈' 날, 나머지는 '계획' 날이 기본이다.
- 날짜·수치는 "확인 필요"로 두고 단정하지 않는다(루틴이 그날 1차 출처로 다시 확인한다).
- 이후 계획은 주간 리포트 날 루틴이 이어 쓴다.
